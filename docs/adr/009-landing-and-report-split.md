# ADR 009 — 랜딩과 리포트를 나누고, 다시 온 사람은 자동으로 통과시킨다

- **상태**: 확정 · 구현 완료
- **날짜**: 2026-08-14
- **관련**: [ADR 007](007-remove-mood-badge.md), 설계서 `docs/specs/2026-08-14-report-page-redesign.md`

## 맥락

이 앱은 개인 도구가 아니라 **대중 공개 서비스**다. 그런데 화면은 이미 이 앱을 아는 사람
기준으로 되어 있었다. 처음 온 사람은 왜 목표주가가 아니라 범위를 보여주는지,
왜 방향을 안 맞히는지 모른 채 숫자만 본다.

"방향은 예측하지 않는다"는 입장([ADR 001](001-drop-direction-forecast.md))은
**처음 보는 사람에게는 이상하게 들린다.** 서비스가 무엇인지 먼저 말할 자리가 필요했다.

동시에, 매일 확인하는 사람에게 소개 화면은 순수한 마찰이다. 매번 한 번 더 눌러야 한다.

## 결정

**페이지를 둘로 나눈다.**

```
index.html     랜딩 — 서비스 소개 + 종목 고르기
report.html    리포트 — 데이터·모델·차트·모든 섹션
```

그리고 `/`에 들어오면 **`<head>` 인라인 스크립트**가 화면이 그려지기 전에 판단한다.

```
1. 주소에 ?code=XXXX 가 있으면      → report.html?code=XXXX 로 이동
2. 마지막에 본 종목 기억이 있으면    → report.html?code=기억한종목 으로 이동
3. 둘 다 없으면                     → 랜딩을 보여준다 (진짜 첫 방문)
```

- 이동은 `location.replace()`. 히스토리에 남지 않아야 뒤로 가기가 루프에 빠지지 않는다.
- **`<head>`에서 처리해야** 랜딩이 깜빡이지 않는다. `<body>` 렌더 전에 끝낸다.
- 1번 덕분에 **기존에 공유된 `?code=` 링크가 그대로 작동한다.** 리다이렉트를 넣지 않았다.
- PWA `start_url`은 `./report.html?src=pwa` — 홈 화면에서 여는 사람은 매일 보는 사람이다.
  이미 설치한 사람의 아이콘이 옛 주소로 열려도 2번 규칙이 받아서 리포트로 넘긴다.

**리포트 상단에 홈 버튼을 둔다** → `./?home=1`

처음에는 링크를 두지 않기로 했으나, **기존 사용자가 랜딩을 아예 볼 수 없다는 점이
실제로 확인됐다.** 랜딩은 앞으로 서비스 소개 겸 전체 대시보드로 발전할 자리이므로,
이미 쓰던 사람도 원할 때 갈 수 있어야 한다.

> **홈 링크에는 반드시 `?home=1`을 단다.** 그냥 `./`로 보내면 랜딩이 기억된 종목을 읽고
> 곧바로 리포트로 되돌려 보낸다 — 버튼이 아무 일도 안 하는 것처럼 보인다.

## 근거

| | 첫 방문자 | 매일 보는 사람 |
|---|---|---|
| 랜딩 없음 | 이 앱이 뭔지 모른 채 숫자를 본다 | 마찰 없음 |
| 항상 랜딩부터 | 이해하고 들어간다 | **매번 한 번 더 눌러야 한다** |
| **자동 통과 (채택)** | 이해하고 들어간다 | 마찰 없음 |

랜딩의 종목 목록은 `symbols.json`에서 자동으로 그린다.
종목이 30개가 돼도 랜딩 코드를 고칠 필요가 없다 — 로드맵 4번(AI 카테고리)을 대비한 구조다.

## 버린 대안

| 대안 | 왜 버렸나 |
|---|---|
| 랜딩 없이 리포트 첫 화면이 겸한다 | 두 줄로는 서비스의 얼굴이 되기 어렵다 |
| 항상 랜딩부터 보여준다 | 매일 보는 사람과 홈 화면 아이콘 사용자에게 마찰. 이 앱은 매일 보는 용도다 |
| 상단 탭으로 화면을 3개로 쪼갠다 | **정보가 탭 뒤로 숨는다.** 이 앱은 한계와 검증 결과를 끝까지 보여주는 것이 정체성이다. 접기는 제목이 보이지만 탭은 그것도 안 보인다 |
| 종목별 정적 주소(`/005930/`) | 별도 검토 후 보류. 설계서 §5.4 — 위험 넷 중 셋이 "고장 나도 화면에 티가 안 나는" 종류였고, 넷째(퍼진 주소는 되돌릴 수 없음)는 장치로 막을 수 없다 |

## 이 결정이 드러낸 결함 하나

페이지를 둘로 나누자 **서비스 워커가 두 페이지를 뒤섞는 문제**가 드러났다.
`sw.js`가 모든 화면 응답을 `./index.html` 키 하나에 저장하고 오프라인에서도 항상
그것을 돌려주고 있었다. 페이지가 하나일 때는 문제가 없었지만, 둘이 되자 서로를 덮어썼다 —
**오프라인에서 `/`를 열면 리포트가 떴다.**

실제로 재현한 뒤 캐시 키를 주소별(쿼리 제거)로 바꾸고 폴백을
`그 주소 → 랜딩 → 루트` 순서로 고쳤다. 페이지를 더 늘릴 때 같은 함정을 다시 만들지 말 것.

## 되돌리려면

**되돌리기 쉬운 결정이다.** `index.html`을 리포트로 되돌리고 `manifest`의 `start_url`을
`./`로 바꾸면 끝난다. 생성물도, 템플릿도, 빌드 단계도 없다.

랜딩을 없애야 할 이유가 생긴다면 — 예를 들어 첫 방문자가 랜딩에서 이탈하는 비율이
높다고 확인되면 — 그때 판단한다. 지금은 그 데이터가 없다.

**항상 랜딩부터 보여주는 쪽으로 바꾸려면**: 매일 보는 사람이 한 번 더 누르는 비용보다
소개를 매번 보여주는 이득이 크다는 근거가 있어야 한다. 지금은 반대라고 본다.
