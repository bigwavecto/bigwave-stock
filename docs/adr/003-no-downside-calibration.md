# ADR 003 — 하락 확률 과대 예보를 보정하지 않는다

- **상태**: 확정 · 구현 완료
- **날짜**: 2026-08-13
- **관련**: CLAUDE.md 「핵심 규칙 1」, [ADR 001](001-drop-direction-forecast.md)

## 맥락

앱은 "이 가격에 닿을 가능성"(임계값 도달 확률)을 보여준다.
드리프트 0을 가정한 배리어 공식으로 계산한다.

```
P(도달) = 2 · Φ( −|ln(1 + pct/100)| / (σ√h) )
```

이 프로젝트에서 **유일하게 양의 예측력을 낸 확률 예보**다 (상승 임계값 BSS +0.04 ~ +0.18).

그런데 채점해 보니 **하락 쪽이 실제보다 높게 나온다.**

| | 예보 | 실제 |
|---|---|---|
| 하락 임계값 도달 | 17.6% | **11.2%** |

숫자만 보면 명백한 편향이고, 상수 하나만 곱하면 바로 맞출 수 있다.

## 결정

**보정하지 않는다.** 대신 이 사실을 화면에 그대로 밝힌다.

## 근거

편향의 원인이 모델이 아니라 **표본**이기 때문이다.

- 검증 구간(2016-08 ~ 2026-08)에서 삼성전자는 **8.6배**, SK하이닉스는 **48.2배** 올랐다.
- 즉 이 10년은 강한 상승 구간이었고, 그래서 "떨어질 것"이라 말한 예보가 자주 빗나갔다.
- 드리프트 0 가정은 **상승·하락 어느 쪽도 편들지 않겠다**는 뜻이다.
  실제 결과에 맞춰 하락 확률을 낮추는 순간, 그 가정을 버리고
  **"앞으로도 지난 10년처럼 오른다"** 고 말하는 것이 된다.

이는 [ADR 001](001-drop-direction-forecast.md)에서 폐기한 방향 예측을,
확률 쪽 문으로 다시 들여오는 것과 같다.

정리하면:

| | 보정하지 않을 때 | 보정할 때 |
|---|---|---|
| 지난 10년 채점 | 하락 쪽이 조금 보수적 | 정확 |
| 하락장이 오면 | 그대로 작동 | **하락을 계속 과소 예보** |
| 모델이 말하는 것 | "방향은 모른다" | "오를 것이다" |

**보수적으로 틀리는 쪽**을 택했다. 하락 위험을 실제보다 낮게 알려주는 앱은
그 방향으로 틀렸을 때 사용자에게 훨씬 나쁘다.

## 버린 대안

| 대안 | 왜 버렸나 |
|---|---|
| 하락 확률에 보정 계수를 곱한다 | 지난 10년의 상승을 미래에 복사하는 것 |
| 과거 평균 수익률을 드리프트로 넣는다 | 같은 문제. 게다가 ADR 001에서 "과거 평균" 점추정은 이미 랜덤워크에 졌다 |
| 상승 확률도 같이 낮춰 대칭을 맞춘다 | 상승 쪽은 **이미 잘 맞는다**(BSS 양수). 맞는 것을 망가뜨리는 셈 |
| 편향을 화면에 밝히지 않고 그냥 둔다 | 채점 결과를 보여주는 앱이 자기 편향만 감추는 것은 앞뒤가 맞지 않는다 |

## 되돌리려면

보정을 도입하려면 **편향이 표본 탓이 아니라 모델 결함임**을 보여야 한다.

1. **상승·하락이 균형 잡힌 표본**에서도 같은 방향의 편향이 나올 것
   — 예: 하락 구간을 포함한 다른 10년, 또는 장기 횡보한 다른 종목
2. 상승 임계값과 하락 임계값의 **오차 방향이 서로 반대**일 것
   (지금은 둘 다 "상승 구간이었다"로 설명된다)
3. 보정 후 BSS가 **상승·하락 양쪽 모두** 개선될 것 — 한쪽만 좋아지면 표본 맞추기다
4. 보정 상수가 종목별로 크게 갈리지 않을 것 (갈리면 [ADR 002](002-per-symbol-constants.md) 문제로 넘어간다)

> 이 결정은 "숫자가 안 맞는데 왜 안 고치냐"는 지적을 반복해서 받을 만한 종류다.
> 답은 **숫자가 안 맞는 게 아니라, 맞추면 다른 것이 깨진다**는 것이다.
