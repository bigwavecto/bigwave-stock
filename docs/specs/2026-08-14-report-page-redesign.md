# 설계서 — 리포트 화면 재설계 (로드맵 2-3)

- **작성일**: 2026-08-14
- **범위**: 로드맵 2-3 "UI/UX 구조부터 재설계" + 공개 서비스 기본기
- **선행**: 로드맵 2-1(섹션 검증), 2-2(섹션 재구성) 완료
- **관련 결정**: [ADR 001](../adr/001-drop-direction-forecast.md), [ADR 002](../adr/002-per-symbol-constants.md), [ADR 007](../adr/007-remove-mood-badge.md)

## 1. 배경

로드맵 2-1에서 화면 요소를 두 종목 10년치로 검증했고, 2-2에서 검증에 떨어진 것들을
걷어냈다. 남은 것은 **정보의 구조** — 순서, 묶음, 접기, 탐색 방식이다.

설계 도중 전제가 하나 바뀌었다. 이 앱은 **개인 도구가 아니라 대중 공개 서비스**다.
이 전제가 두 가지 판단을 뒤집었다.

| | 개인 도구 전제 | 공개 서비스 전제 |
|---|---|---|
| 단일 HTML 파일 유지 | 브라우저로 더블클릭해 열 수 있어 편하다 | 그건 개발자 편의다. 판단 기준은 **첫 방문 속도**와 **캐시 효율** |
| 성적표 접기 | 이미 아는 내용이라 접어도 된다 | **처음 온 사람이 이 앱을 믿을 유일한 근거**다. 접으면 아무도 안 본다 |

"방향은 예측하지 않는다"는 이 앱의 입장은 **처음 보는 사람에게는 이상하게 들린다.**
그 선언을 정당화하는 것이 성적표이므로, 둘은 붙어 있어야 한다.

## 2. 목표

1. 30초 사용자가 **스크롤 없이** 오늘 필요한 것을 다 보게 한다
2. 정독하는 사람이 근거까지 파고들 수 있게 한다 — **정보를 줄이지 않는다**
3. 처음 온 사람이 첫 화면에서 **이게 뭔지 · 믿을 만한지**를 알게 한다
4. 카카오톡·검색으로 들어오는 경로를 실제로 작동하게 한다
5. 종목이 30개가 돼도(로드맵 4번) 구조가 버티게 한다

## 3. 범위

**포함**

- 첫 화면(요약 블록) 신설
- 섹션 순서·접기 재편
- 종목 탐색을 목록 시트로 교체
- 종목별 정적 주소 생성 + 자산(CSS/JS) 분리
- 공개 기본기: 공유 카드 메타, 검색 노출, 접근성, 첫 로드 성능, 면책 표시 위치

**제외** (각각 별도 작업)

- 회원 로그인 (로드맵 3)
- AI 산업 카테고리 종목 추가 (로드맵 4) — 구조만 대비하고 데이터는 넣지 않는다
- 랜딩페이지 (로드맵 5) — `/`는 당분간 기본 종목 리포트로 둔다
- 관리자 페이지 (로드맵 6)
- 종목별 공유 카드 이미지 자동 생성 — 1단계는 공통 이미지 하나

## 4. 화면 구조

### 4.1 첫 화면 (스크롤 전)

모바일 390px 기준 약 390px 안에 들어와야 한다.

```
┌────────────────────────────────┐
│ 삼성전자 ▾  005930      🟢 최신 │  ← 이름을 누르면 종목 목록 시트
├────────────────────────────────┤
│ 268,000원                      │
│ 어제보다 ▲ 12,500 (+4.9%)      │
│                                │
│ 1주 뒤 이 범위일 가능성이 높아요 │
│ 220,723 ──▓▓▓▓▓▓▓── 325,403원  │
│ 10번 중 8번은 이 안이에요        │
│                                │
│ 지금 흔들림       평소의 3.0배  │
├────────────────────────────────┤
│ 이 앱은 오를지 내릴지 맞히지     │
│ 않아요. 얼마나 흔들릴지만 알려   │
│ 드려요.              왜요? ›    │  → 방법론 섹션으로 이동
│ 지금까지 성적: 범위 적중 80.5% › │  → 성적표 섹션으로 이동
└────────────────────────────────┘
```

**마지막 두 줄이 이 설계의 핵심이다.** "안 맞힌다"는 선언과 그것을 정당화하는 성적을
나란히 둔다. 하나만 있으면 이상해 보이고, 둘이 붙어야 설득이 된다.

기존 요소 처리:

| 기존 | 처리 |
|---|---|
| `.price-row` 5칸 (지금 가격·어제보다·1년 최고·1년 최저·1년 전보다) | 앞 2개만 첫 화면에. 1년 최고/최저/수익률은 "지금 상황" 카드로 이동 |
| `.summary-banner` (원형 흔들림 + 긴 설명문) | 원형은 유지, 긴 설명문은 위 4줄로 압축 |
| 홈 화면 추가 안내(`.install-tip`) | 첫 화면 아래로 내린다. 첫 방문자에게 설치 권유가 먼저 오면 안 된다 |
| 조사 자료 오래됨 경고(`.stale-warn`) | 해당 카드 안으로 이동. 전역 경고는 첫인상을 해친다 |

`?h=` 로 기간을 고정할 수 있게 한다(1주/2주/1개월). 공유 시 보던 기간이 유지된다.

### 4.2 섹션 순서와 접기

묶음 제목은 2-2에서 만든 4개를 유지한다.

| 묶음 | # | 섹션 | 기본 상태 |
|---|---|---|---|
| 이 앱이 확인한 것 | 1 | 주가 흐름과 앞으로 예상 범위 | 펼침 |
| | 2 | 이 가격에 닿을 가능성 | 펼침 |
| | 3 | 성적표 | **펼침** |
| 벌어지고 있는 일 | 4 | 지금 상황 | 펼침 |
| 사람들이 보는 것 | 5 | 증권사는 어떻게 보나요 | 펼침 |
| | 6 | 주가를 움직이는 것들 | 펼침 |
| 계산 방법 | 7 | 왜 "얼마가 된다"고 말하지 않나요 | **접힘** |

**성적표는 펼쳐 두고, 그 안의 예측 기록 표(날짜별 8열)만 접는다.**
요약 성적(구간 적중률·평균 범위 폭·비교 기준 대비)은 항상 보이고,
원본 기록은 볼 사람만 펼친다.

접기는 **`<details>`/`<summary>` 표준 요소**를 쓴다. 자바스크립트 없이 동작하고
스크린리더·키보드 조작·인쇄가 공짜로 따라온다. 직접 만든 토글은 쓰지 않는다.

접힌 섹션은 **첫 화면의 `›` 링크로 이동할 때 자동으로 펼쳐진다**
(`details.open = true` 후 스크롤).

### 4.3 종목 탐색

상단 종목 이름(`삼성전자 ▾`)을 누르면 아래에서 시트가 올라온다.

```
┌───────────────────────┐
│ 종목 고르기         ✕ │
├───────────────────────┤
│ 🔍 종목 이름·코드 검색 │
│                       │
│ 반도체                 │
│   삼성전자   268,000 ▲ │
│   SK하이닉스 812,000 ▲ │
└───────────────────────┘
```

- 카테고리는 `symbols.json`에 `category` 필드를 더해 표현한다.
  값이 없으면 "전체" 한 묶음으로 나온다 — **로드맵 4번 전까지는 이 상태다.**
- 시세는 이미 받아둔 데이터가 있는 종목만 표시하고, 없으면 이름만 보여준다.
- `role="dialog"` + `aria-modal`, ESC·배경 클릭·닫기 버튼으로 닫히고,
  열릴 때 검색창에 초점이 간다. 차트 확대 모달과 같은 규칙을 쓴다.
- 종목이 5개 이하면 검색창을 숨긴다.

## 5. 주소와 파일 구조

### 5.1 왜 바꾸는가

카카오톡·페이스북·구글 크롤러는 **자바스크립트를 실행하지 않는다.**
지금은 `?code=000660`으로 들어와도 HTML의 제목이 "삼성전자 주가 리포트"라서,
하이닉스 링크를 공유하면 **삼성전자로 뜬다.** 종목마다 정적 HTML이 있어야 해결된다.

종목별 HTML을 만들면 CSS·JS가 종목마다 중복되므로, **자산 분리가 함께 필요하다.**
이것이 파일을 쪼개는 진짜 이유다 — 개발 편의가 아니라 공유·검색·캐시 때문이다.

### 5.2 구조

```
templates/report.html     HTML 소스 (플레이스홀더 포함). HTML은 여기만 고친다
assets/app.css            공통 스타일
assets/app.js             공통 로직 (모델·렌더·차트)
scripts/build_pages.js    symbols.json을 읽어 아래를 생성
─────────────────────────────────────────────
index.html                생성물 — 앱 진입점
005930/index.html         생성물 — 삼성전자 고정 주소
000660/index.html         생성물 — SK하이닉스 고정 주소
sitemap.xml               생성물
robots.txt                생성물
```

**생성물은 저장소에 커밋한다.** Vercel에 빌드 단계를 두지 않는다 —
지금 배포가 "빌드 없는 정적 파일"이라 안전하고 빠르다.
`scripts/update_daily.js`가 매일 데이터를 갱신한 뒤 `build_pages.js`를 이어서 돌린다.

### 5.3 각 주소가 하는 일

| 주소 | 역할 | 종목 결정 |
|---|---|---|
| `/` | 앱 진입점(PWA `start_url`). **지금과 동작이 같다** | `?code=` → localStorage 마지막 선택 → 첫 종목 |
| `/005930/` | 공유·검색용 고정 주소 | `<body data-code="005930">` 로 고정 |

- **옛 링크 `/?code=000660`은 그대로 작동한다.** 리다이렉트를 넣지 않는다.
- 앱 안에서 종목을 바꾸면 `history.replaceState`로 주소를 `/000660/`으로 바꾼다.
- `/`의 `<link rel="canonical">`은 기본 종목 페이지를 가리킨다(중복 색인 방지).
- 로드맵 5번에서 랜딩이 생기면 `/`가 랜딩이 되고, 이 구조는 그대로 남는다.

### 5.4 종목별 메타 (템플릿 플레이스홀더)

```html
<title>{{name}}({{code}}) 주가 예상 범위 · 얼마나 흔들릴까요</title>
<meta name="description" content="{{name}} 주가가 앞으로 1주~1개월 어느 범위에서
  움직일지, 특정 가격에 닿을 가능성이 얼마인지 매일 알려드려요.
  오를지 내릴지는 예측하지 않습니다. 10년치로 검증한 범위만 보여드려요.">
<link rel="canonical" href="https://stock.bigwave.im/{{code}}/">
<meta property="og:title" content="…">
<meta property="og:description" content="…">
<meta property="og:url" content="…">
<meta property="og:image" content="https://stock.bigwave.im/icons/og.png">
<meta name="twitter:card" content="summary_large_image">
```

og 이미지는 1단계에서 **공통 이미지 하나**(1200×630)를 쓴다.
기존 아이콘과 같은 방식으로 Node에서 PNG를 직접 인코딩해 만든다
(`scripts/tools/make_og.js`). 종목명이 들어간 이미지는 나중 과제로 둔다.

## 6. 공개 서비스 기본기

### 6.1 접근성

- 접기는 `<details>`, 시트는 `role="dialog"` + 초점 관리
- 랜드마크 — `<header>` / `<nav>` / `<main>` / `<footer>`
- 표에 시각적으로 숨긴 `<caption>`, `<th scope="col">`
- **색만으로 정보를 전달하지 않는다** — ▲▼ 기호 병행(이미 지키고 있다)
- 본문 명도 대비 4.5:1 이상 확인. 특히 `--sub`(#5b6785)와 `.warnline` 안 글자
- `prefers-reduced-motion: reduce`면 차트 애니메이션을 끈다
- 터치 목표 최소 44px 유지(이미 적용)

### 6.2 첫 로드 성능

- CSS·JS 외부 파일 + 1년 캐시(파일명에 버전 쿼리)
- `Chart.js`와 `app.js`를 **`defer`** 로 — 지금은 `<head>`에서 동기 로드라 첫 화면을 막는다
- 첫 화면에 필요한 스타일이 늦게 오지 않도록, 요약 블록 스타일만 인라인으로 남긴다
- 차트는 화면에 들어올 때 그린다(`IntersectionObserver`)

### 6.3 면책·법적 표시

- 첫 화면 요약 블록 바로 아래 한 줄 — "참고용이에요. 투자 권유가 아니에요."
- 전문은 지금처럼 맨 아래 유지
- **투자 권유로 읽힐 표현 금지 규칙은 그대로다**(CLAUDE.md 문체 규칙)

### 6.4 검색 노출

- `sitemap.xml` — `/`와 모든 `/<code>/`. `lastmod`는 데이터 갱신일
- `robots.txt` — 전체 허용, sitemap 위치 명시
- 종목별 `<h1>`에 종목명과 코드를 넣는다

## 8. 위험과 대응

| 위험 | 왜 위험한가 | 대응 |
|---|---|---|
| **예측 기록 유실** | 주소가 바뀌어도 `localStorage`는 출처 단위라 유지되지만, 키 이름을 건드리면 끝이다 | 키 생성 코드를 손대지 않는다. 배포 전 옛 주소·새 주소 양쪽에서 기록이 이어지는지 확인 |
| 서비스 워커가 옛 파일에 갇힘 | 경로가 늘어나 캐시 목록이 바뀐다 | `CACHE` 버전을 올리고, 새 경로(`/assets/`, `/<code>/`)를 포함. HTML·데이터는 지금처럼 네트워크 우선 |
| 모델 이중 구현이 조용히 어긋남 | 코드가 파일을 옮기면 `parity.js`가 못 찾는다 | `parity.js`를 새 경로에 맞춰 고치고, **일부러 깨뜨려 차단되는지 확인**(하네스 0단계와 같은 방법) |
| 생성물과 템플릿이 어긋남 | 사람이 생성물을 직접 고치면 다음 빌드에 날아간다 | 생성 파일 맨 위에 "이 파일은 자동 생성됩니다. `templates/report.html`을 고치세요" 주석. `preflight.js`가 **`build_pages.js`를 메모리에서 다시 돌려 생성물과 글자 단위로 비교**하고, 다르면 커밋을 막는다 |
| Vercel 캐시 헤더가 새 경로를 안 잡음 | `/005930/index.html`이 1년 캐시되면 갱신이 안 보인다 | `vercel.json`에서 HTML 전체를 `must-revalidate`로, `/assets/`만 1년 |
