# 설계서 — 랜딩 + 리포트 화면 재설계 (로드맵 2-3, 5번 일부)

- **작성일**: 2026-08-14 (2차 개정 — 랜딩 페이지 도입 반영)
- **범위**: 로드맵 2-3 "UI/UX 구조부터 재설계" + 로드맵 5번(랜딩)의 앞부분
- **선행**: 2-1(섹션 검증), 2-2(섹션 재구성) 완료
- **관련 결정**: [ADR 001](../adr/001-drop-direction-forecast.md), [ADR 002](../adr/002-per-symbol-constants.md), [ADR 007](../adr/007-remove-mood-badge.md)

## 1. 배경

2-1에서 화면 요소를 두 종목 10년치로 검증했고, 2-2에서 검증에 떨어진 것들을 걷어냈다.
남은 것은 **정보의 구조** — 순서, 묶음, 접기, 탐색 방식이다.

설계 도중 전제가 확인됐다. 이 앱은 **개인 도구가 아니라 대중 공개 서비스**다.
이 전제가 두 가지를 바꿨다.

**① 성적표를 접지 않는다.**
개인 도구면 이미 아는 내용이라 접어도 된다. 공개 서비스에서는
**처음 온 사람이 이 앱을 믿을 유일한 근거**다. "방향은 예측하지 않는다"는 입장은
처음 보는 사람에게 이상하게 들리고, 그 선언을 정당화하는 것이 성적표다. 둘은 붙어 있어야 한다.

**② 서비스의 얼굴이 필요하다 → 랜딩 페이지.**
다만 매일 확인하는 사람에게 랜딩은 순수한 마찰이다. 그래서
**처음 온 사람만 보고, 다시 온 사람은 자동으로 통과**하는 구조를 택했다(§5.2).

## 2. 목표

1. 처음 온 사람이 **랜딩에서** 이게 뭔지 알고 종목을 고른다
2. 다시 온 사람은 **랜딩을 보지 않고** 바로 자기 종목 리포트로 간다
3. 30초 사용자가 리포트에서 **스크롤 없이** 오늘 필요한 것을 다 본다
4. 정독하는 사람이 근거까지 파고들 수 있다 — **정보를 줄이지 않는다**
5. 종목이 30개가 돼도(로드맵 4번) 랜딩과 리포트 모두 **다시 만들지 않아도 된다**

## 3. 범위

**포함**

- 랜딩 페이지 신설 (`index.html`)
- 리포트 첫 화면(요약 블록) 신설
- 섹션 순서·접기 재편
- 종목 탐색을 목록 시트로 교체
- 전 종목 요약 데이터(`data/summary.json`) 생성
- 접근성, 첫 로드 성능, 면책 표시 위치, 공유·검색 메타

**제외**

| 항목 | 이유 |
|---|---|
| 종목별 정적 주소(`/005930/`) + 자산 분리 | **보류.** §5.4 참조 |
| 회원 로그인 | 로드맵 3 |
| AI 산업 카테고리 종목 데이터 | 로드맵 4 — 구조만 대비하고 데이터는 넣지 않는다 |
| 관리자 페이지 | 로드맵 6 |

## 4. 화면 구조

### 4.1 랜딩 (`/`)

```
          [아이콘]
        주가 리포트
   앞으로 얼마나 흔들릴지 알려드려요

┌──────────────────────────────────┐
│ ✕  오를지 내릴지는 맞히지 않아요   │
│    10년치로 해봤는데 안 맞았거든요  │
│                                  │
│ ✓  대신 "이 범위 안에 있을 거예요" │
│    를 알려드려요                  │
│    10번 중 8번은 그 안에 들어와요  │
│                                  │
│ ✓  진짜 맞는지 매일 채점해서       │
│    성적표로 보여드려요             │
└──────────────────────────────────┘

  어떤 종목을 보시겠어요?

┌──────────────────────────────────┐
│ 삼성전자            268,000원     │
│ 005930              ▲ +4.9%      │
└──────────────────────────────────┘
┌──────────────────────────────────┐
│ SK하이닉스          812,000원     │
│ 000660              ▲ +2.1%      │
└──────────────────────────────────┘

  참고용이에요. 투자 권유가 아니에요.
  평일 오후 4시 40분에 자동으로 갱신돼요.
```

**규칙**

- 종목 목록은 `data/symbols.json`에서 **자동으로 그린다.**
  종목이 30개가 돼도 랜딩 코드를 고칠 필요가 없다.
- 시세는 `data/summary.json`(§5.5)에서 읽는다. **없으면 이름과 코드만 보여준다** —
  맥락 데이터와 같은 원칙으로, 못 받아도 랜딩은 정상 동작한다.
- **랜딩에는 종목별 숫자를 쓰지 않는다.** "10번 중 8번"은 두 종목 모두에서
  성립하는 공통 사실이라 안전하지만, 종목마다 다른 값(변동성·신고가 효과 등)을
  랜딩에 쓰면 [ADR 002](../adr/002-per-symbol-constants.md) 위반이 된다.
- 차트 라이브러리를 불러오지 않는다. 랜딩은 아주 가볍게 유지한다.

### 4.2 리포트 첫 화면 (`/report.html`, 스크롤 전)

모바일 390px 기준 약 390px 안에 들어와야 한다.

```
┌────────────────────────────────┐
│ 삼성전자 ▾  005930      🟢 최신 │  ← 이름을 누르면 종목 목록 시트
├────────────────────────────────┤
│ 268,000원                      │
│ 어제보다 ▲ 12,500 (+4.9%)      │
│                                │
│ 1주 뒤 이 범위일 가능성이 높아요 │
│ 220,723 ──▓▓▓▓▓▓▓── 325,403원  │
│ 10번 중 8번은 이 안이에요        │
│                                │
│ 지금 흔들림       평소의 3.0배  │
├────────────────────────────────┤
│ 오를지 내릴지는 맞히지 않아요.   │
│ 얼마나 흔들릴지만 알려드려요.    │
│                      왜요? ›    │  → 방법론 섹션으로 이동
│ 지금까지 성적: 범위 적중 80.5% › │  → 성적표 섹션으로 이동
└────────────────────────────────┘
```

**마지막 두 줄이 핵심이다.** "안 맞힌다"는 선언과 그것을 정당화하는 성적을 나란히 둔다.
하나만 있으면 이상해 보이고, 둘이 붙어야 설득이 된다.
랜딩을 건너뛰고 들어온 사람(대부분의 재방문자)에게도 이 맥락이 남아야 한다.

기존 요소 처리:

| 기존 | 처리 |
|---|---|
| `.price-row` 5칸 | 앞 2개(지금 가격·어제보다)만 첫 화면에. 나머지 3개는 "지금 상황" 카드로 이동 |
| `.summary-banner` | 원형 흔들림 표시는 유지, 긴 설명문은 위 4줄로 압축 |
| 홈 화면 추가 안내(`.install-tip`) | 첫 화면 아래로 내린다 |
| 조사 자료 오래됨 경고(`.stale-warn`) | 해당 카드 안으로 이동 |
| 상단 종목 버튼 줄(`.symbar`) | 종목 이름 탭 + 시트로 교체(§4.4) |

`?h=` 로 기간(1주/2주/1개월)을 고정할 수 있게 한다. 공유했을 때 보던 기간이 유지된다.

### 4.3 섹션 순서와 접기

묶음 제목은 2-2에서 만든 4개를 유지한다.

| 묶음 | # | 섹션 | 기본 상태 |
|---|---|---|---|
| 이 앱이 확인한 것 | 1 | 주가 흐름과 앞으로 예상 범위 | 펼침 |
| | 2 | 이 가격에 닿을 가능성 | 펼침 |
| | 3 | 성적표 | **펼침** |
| 벌어지고 있는 일 | 4 | 지금 상황 | 펼침 |
| 사람들이 보는 것 | 5 | 증권사는 어떻게 보나요 | 펼침 |
| | 6 | 주가를 움직이는 것들 | 펼침 |
| 계산 방법 | 7 | 왜 "얼마가 된다"고 말하지 않나요 | **접힘** |

**성적표는 펼쳐 두고, 그 안의 예측 기록 표(날짜별 8열)만 접는다.**
요약 성적(구간 적중률·평균 범위 폭·비교 기준 대비)은 항상 보이고,
원본 기록은 볼 사람만 펼친다.

접기는 **`<details>`/`<summary>` 표준 요소**를 쓴다. 자바스크립트 없이 동작하고
스크린리더·키보드 조작·인쇄가 공짜로 따라온다. 직접 만든 토글은 쓰지 않는다.

접힌 섹션은 첫 화면의 `›` 링크로 이동할 때 **자동으로 펼쳐진다**
(`details.open = true` 후 스크롤).

### 4.4 종목 시트 (리포트 안)

상단 종목 이름(`삼성전자 ▾`)을 누르면 아래에서 시트가 올라온다.

```
┌───────────────────────┐
│ 종목 고르기         ✕ │
├───────────────────────┤
│ 🔍 종목 이름·코드 검색 │
│                       │
│ 반도체                 │
│   삼성전자   268,000 ▲ │
│   SK하이닉스 812,000 ▲ │
└───────────────────────┘
```

- 카테고리는 `symbols.json`에 `category` 필드를 더해 표현한다.
  값이 없으면 "전체" 한 묶음으로 나온다 — 로드맵 4번 전까지는 이 상태다.
- 시세는 랜딩과 같은 `data/summary.json`을 쓴다.
- `role="dialog"` + `aria-modal`, ESC·배경 클릭·닫기 버튼으로 닫힌다.
  열릴 때 검색창에 초점이 가고, 닫으면 **원래 버튼으로 초점이 돌아온다.**
  차트 확대 모달과 같은 규칙을 쓴다.
- 종목이 5개 이하면 검색창을 숨긴다.

## 5. 페이지·주소 구조

### 5.1 두 페이지

```
index.html     랜딩 (신설)
report.html    리포트 (지금 index.html을 git mv로 이름만 변경 — 기록 보존)
```

- 파일을 **손으로 만든다.** 템플릿에서 찍어내지 않는다.
- 계산 코드는 `report.html`에 그대로 남는다 →
  **모델 이중 구현 검사(`parity.js`)는 파일명만 바꾸면 된다.**
- 랜딩과 리포트는 스타일을 공유하지 않는다. 랜딩용 최소 CSS(1~2KB)를 따로 쓴다.
  중복이 조금 생기지만, 공통 CSS 파일을 만드는 것은 §5.4에서 보류한 자산 분리에 해당한다.

### 5.2 자동 통과 규칙 — 이 설계의 핵심

`/`(랜딩)에 들어오면 **`<head>` 안 인라인 스크립트**가 화면이 그려지기 전에 판단한다.

```
1. 주소에 ?code=XXXX 가 있으면      → report.html?code=XXXX 로 이동
2. 마지막에 본 종목 기억이 있으면    → report.html?code=기억한종목 으로 이동
3. 둘 다 없으면                     → 랜딩을 보여준다 (진짜 첫 방문)
```

- 이동은 `location.replace()`를 쓴다. 뒤로 가기를 눌렀을 때
  랜딩 ↔ 리포트를 오가는 루프가 생기지 않는다.
- **`<head>`에서 처리해야** 랜딩이 잠깐 깜빡이지 않는다. `<body>` 렌더 전에 끝낸다.
- 1번 덕분에 **기존에 공유된 `stock.bigwave.im/?code=000660` 링크가 그대로 작동한다.**
- **리포트 상단에 홈 버튼을 둔다** → `./?home=1`
  (2026-08-14 추가 결정. 처음에는 링크를 두지 않기로 했으나, 기존 사용자가 랜딩을
  아예 볼 수 없다는 점이 실제로 확인됐다. 랜딩은 앞으로 서비스 소개 겸 전체 대시보드로
  발전할 자리이므로, 이미 쓰던 사람도 원할 때 갈 수 있어야 한다.)
- **홈 링크는 반드시 `?home=1`을 달아야 한다.** 그냥 `./`로 보내면 랜딩이
  "마지막에 본 종목"을 읽고 곧바로 리포트로 되돌려 보낸다 — 버튼이 아무 일도 안 하는 것처럼 보인다.

### 5.3 PWA(홈 화면 아이콘)

- `manifest.webmanifest`의 `start_url`을 `./report.html?src=pwa`로 바꾼다.
  홈 화면에서 여는 사람은 매일 보는 사람이므로 리포트로 직행하는 것이 맞다.
- 이미 설치한 사람의 아이콘이 옛 주소(`./?src=pwa`)로 열려도
  §5.2의 2번 규칙이 받아서 리포트로 넘긴다. **깨지지 않는다.**
- `name`·`short_name`·`description`이 "삼성전자"로 고정돼 있다.
  여러 종목을 지원하므로 **종목 중립 문구로 바꾼다.**

### 5.4 종목별 정적 주소는 여전히 보류

`/005930/` 같은 종목별 주소는 만들지 않는다. 이유는 앞선 검토 그대로다 —
바꿨을 때 생기는 위험 넷 중 셋이 "고장 나도 화면에 티가 안 나는" 종류였고,
넷째(퍼진 주소는 되돌릴 수 없음)는 장치로 막을 수 없다.
지금은 방문자가 적어 얻는 것의 크기를 모른다.

**따라서 카카오톡·검색에서 종목별 구분은 여전히 안 된다.**
아래 중 하나가 관찰되면 다시 검토한다.

- 링크 공유 유입이 생겼는데 종목이 틀리게 표시돼 문제가 된 사례가 나올 때
- 검색 유입을 늘리는 것이 목표가 될 때
- 종목이 늘어 한 페이지가 감당하기 어려워질 때

### 5.5 `data/summary.json` (신설)

랜딩과 종목 시트가 전 종목 시세를 한 번에 읽기 위한 작은 파일.

```json
{ "updated": "2026-08-13",
  "rows": [ { "code":"005930", "name":"삼성전자", "c":268000, "chg":4.89 } ] }
```

- `scripts/update_daily.js`가 전 종목을 순회하면서 마지막에 쓴다.
- **실패해도 전체를 중단시키지 않는다** — 수급·시장지표와 같은 원칙.
- 종목이 30개여도 몇 KB다. 랜딩이 종목별 `prices.json`을 30개 받는 것을 막는다.

## 6. 공개 서비스 기본기

### 6.1 접근성

- 접기는 `<details>`, 시트는 `role="dialog"` + 초점 관리(열 때 검색창, 닫을 때 원래 버튼)
- 랜드마크 — `<header>` / `<nav>` / `<main>` / `<footer>`
- 표에 시각적으로 숨긴 `<caption>`, `<th scope="col">`
- **색만으로 정보를 전달하지 않는다** — ▲▼ 기호 병행(이미 지키고 있다)
- 본문 명도 대비 4.5:1 이상 확인. 특히 `--sub`(#5b6785)와 `.warnline` 안 글자
- `prefers-reduced-motion: reduce`면 차트 애니메이션을 끈다
- 터치 목표 최소 44px 유지(이미 적용). 랜딩의 종목 버튼은 넉넉히 잡는다

### 6.2 첫 로드 성능

- 랜딩은 Chart.js를 **아예 불러오지 않는다**
- 리포트의 Chart.js를 **`defer`** 로 — 지금은 `<head>`에서 동기 로드라 첫 화면을 막는다
- 차트는 화면에 들어올 때 그린다(`IntersectionObserver`)

### 6.3 면책·법적 표시

- 랜딩 하단에 한 줄, 리포트 첫 화면 요약 아래에 한 줄
- 전문은 지금처럼 리포트 맨 아래 유지
- **투자 권유로 읽힐 표현 금지 규칙은 그대로다**(CLAUDE.md 문체 규칙)

### 6.4 공유·검색 메타

- 랜딩: 제목·설명·`og:` 태그를 제대로 넣는다. 여기가 대표 페이지다
- 리포트: 지금 `<title>`이 "삼성전자"로 고정돼 있어 **하이닉스 링크를 공유하면 틀린 정보가 나간다.**
  종목별로는 못 맞추므로 **종목 중립 문구**로 바꾼다.
  (자바스크립트가 뜨면 지금처럼 종목명으로 바뀌는 동작은 그대로 둔다)
- `og:image`는 공통 이미지 하나(1200×630). 기존 아이콘과 같은 방식으로
  Node에서 PNG를 직접 인코딩해 만든다(`scripts/tools/make_og.js`)
- `robots.txt` + `sitemap.xml`(`/`와 `/report.html`) 추가

**이건 틀린 것을 고치는 작업이지 유입을 늘리는 작업이 아니다.** 그 구분을 유지한다.

## 7. 유지해야 하는 것 (깨뜨리면 안 되는 것)

## 8. 위험과 대응

### 8.1 서비스 워커가 두 페이지를 뒤섞는다 ⚠️ 먼저 고칠 것

**지금 `sw.js`는 모든 화면 응답을 `./index.html` 키 하나에 저장하고,
오프라인일 때도 항상 `./index.html`을 돌려준다**(75·78번 줄).

페이지가 둘이 되면 **서로를 덮어쓴다.** 리포트를 보고 나면 캐시의 `index.html` 자리에
리포트가 들어가고, 오프라인에서 랜딩을 열면 리포트가 뜬다. 반대도 마찬가지다.

> **대응**: 캐시 키를 요청 주소(쿼리 제거) 기준으로 바꾸고,
> 폴백은 `그 페이지 → index.html` 순으로 찾게 한다.
> `SHELL` 목록에 `./report.html`을 넣는다. `CACHE` 버전을 올린다.
> **서버를 끈 상태에서 랜딩과 리포트를 각각 열어 확인한다.**

### 8.2 나머지

| 위험 | 왜 위험한가 | 대응 |
|---|---|---|
| 랜딩이 깜빡인다 | 랜딩이 그려진 뒤 이동하면 재방문자가 매번 흰 화면을 본다 | `<head>` 인라인 스크립트에서 `location.replace()`. 화면 그리기 전에 끝낸다 |
| 뒤로 가기 루프 | 랜딩 → 리포트 → 뒤로 → 랜딩 → 리포트 … | `location.replace()`는 히스토리에 안 남는다 |
| 랜딩을 다시 볼 방법이 없다 | 운영·확인이 어렵다 | `/?home=1`로 강제 표시 |
| 접기가 "정보를 숨긴다"로 읽힘 | 한계까지 다 보여주는 것이 이 앱의 정체성 | 접는 것은 방법론과 예측 기록 표 **둘뿐**. 제목은 항상 보이고, 첫 화면 링크로 들어가면 자동으로 펼쳐진다 |
| 첫 화면이 390px를 넘음 | "스크롤 없이 끝난다"는 목표가 깨진다 | iframe 폭 검사로 실측. 넘으면 면책 한 줄을 아래로 내린다 |
| 캐시 버전을 안 올림 | 사용자가 옛 화면에 갇힌다 | `preflight.js`가 이미 경고한다 — 대상 파일에 `report.html`을 추가해야 한다 |
