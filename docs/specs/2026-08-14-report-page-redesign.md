# 설계서 — 리포트 화면 재설계 (로드맵 2-3)

- **작성일**: 2026-08-14 (주소 구조 관련 결정 반영해 개정)
- **범위**: 로드맵 2-3 "UI/UX 구조부터 재설계"
- **선행**: 로드맵 2-1(섹션 검증), 2-2(섹션 재구성) 완료
- **관련 결정**: [ADR 001](../adr/001-drop-direction-forecast.md), [ADR 002](../adr/002-per-symbol-constants.md), [ADR 007](../adr/007-remove-mood-badge.md)

## 1. 배경

로드맵 2-1에서 화면 요소를 두 종목 10년치로 검증했고, 2-2에서 검증에 떨어진 것들을
걷어냈다. 남은 것은 **정보의 구조** — 순서, 묶음, 접기, 탐색 방식이다.

설계 도중 전제가 하나 확인됐다. 이 앱은 **개인 도구가 아니라 대중 공개 서비스**다.
이 전제가 한 가지 판단을 뒤집었다.

| | 개인 도구 전제 | 공개 서비스 전제 |
|---|---|---|
| 성적표 접기 | 이미 아는 내용이라 접어도 된다 | **처음 온 사람이 이 앱을 믿을 유일한 근거**다. 접으면 아무도 안 본다 |

"방향은 예측하지 않는다"는 이 앱의 입장은 **처음 보는 사람에게는 이상하게 들린다.**
그 선언을 정당화하는 것이 성적표이므로, 둘은 붙어 있어야 한다.

**파일 구조는 지금 그대로 둔다** — 근거는 §5.

## 2. 목표

1. 30초 사용자가 **스크롤 없이** 오늘 필요한 것을 다 보게 한다
2. 정독하는 사람이 근거까지 파고들 수 있게 한다 — **정보를 줄이지 않는다**
3. 처음 온 사람이 첫 화면에서 **이게 뭔지 · 믿을 만한지**를 알게 한다
4. 종목이 30개가 돼도(로드맵 4번) 구조가 버티게 한다

## 3. 범위

**포함**

- 첫 화면(요약 블록) 신설
- 섹션 순서·접기 재편
- 종목 탐색을 목록 시트로 교체
- 접근성 — 표준 요소 사용, 초점 관리, 명도 대비, 움직임 줄이기
- 첫 로드 성능 — 차트 라이브러리가 첫 화면을 막지 않게
- 면책 표시 위치
- 공유·검색 메타 — **지금 구조에서 할 수 있는 만큼만** (§6.4)

**제외**

| 항목 | 이유 |
|---|---|
| 종목별 정적 주소 + 자산(CSS/JS) 분리 | **사용자 결정으로 보류.** §5 참조 |
| 회원 로그인 | 로드맵 3 |
| AI 산업 카테고리 종목 데이터 | 로드맵 4 — 구조만 대비하고 데이터는 넣지 않는다 |
| 랜딩페이지 | 로드맵 5 |
| 관리자 페이지 | 로드맵 6 |

## 4. 화면 구조

### 4.1 첫 화면 (스크롤 전)

모바일 390px 기준 약 390px 안에 들어와야 한다.

```
┌────────────────────────────────┐
│ 삼성전자 ▾  005930      🟢 최신 │  ← 이름을 누르면 종목 목록 시트
├────────────────────────────────┤
│ 268,000원                      │
│ 어제보다 ▲ 12,500 (+4.9%)      │
│                                │
│ 1주 뒤 이 범위일 가능성이 높아요 │
│ 220,723 ──▓▓▓▓▓▓▓── 325,403원  │
│ 10번 중 8번은 이 안이에요        │
│                                │
│ 지금 흔들림       평소의 3.0배  │
├────────────────────────────────┤
│ 이 앱은 오를지 내릴지 맞히지     │
│ 않아요. 얼마나 흔들릴지만 알려   │
│ 드려요.              왜요? ›    │  → 방법론 섹션으로 이동
│ 지금까지 성적: 범위 적중 80.5% › │  → 성적표 섹션으로 이동
└────────────────────────────────┘
```

**마지막 두 줄이 이 설계의 핵심이다.** "안 맞힌다"는 선언과 그것을 정당화하는 성적을
나란히 둔다. 하나만 있으면 이상해 보이고, 둘이 붙어야 설득이 된다.

기존 요소 처리:

| 기존 | 처리 |
|---|---|
| `.price-row` 5칸 (지금 가격·어제보다·1년 최고·1년 최저·1년 전보다) | 앞 2개만 첫 화면에. 나머지 3개는 "지금 상황" 카드로 이동 |
| `.summary-banner` (원형 흔들림 + 긴 설명문) | 원형은 유지, 긴 설명문은 위 4줄로 압축 |
| 홈 화면 추가 안내(`.install-tip`) | 첫 화면 아래로 내린다. 첫 방문자에게 설치 권유가 먼저 오면 안 된다 |
| 조사 자료 오래됨 경고(`.stale-warn`) | 해당 카드 안으로 이동. 전역 경고는 첫인상을 해친다 |

`?h=` 로 기간(1주/2주/1개월)을 고정할 수 있게 한다. 공유했을 때 보던 기간이 유지된다.

### 4.2 섹션 순서와 접기

묶음 제목은 2-2에서 만든 4개를 유지한다.

| 묶음 | # | 섹션 | 기본 상태 |
|---|---|---|---|
| 이 앱이 확인한 것 | 1 | 주가 흐름과 앞으로 예상 범위 | 펼침 |
| | 2 | 이 가격에 닿을 가능성 | 펼침 |
| | 3 | 성적표 | **펼침** |
| 벌어지고 있는 일 | 4 | 지금 상황 | 펼침 |
| 사람들이 보는 것 | 5 | 증권사는 어떻게 보나요 | 펼침 |
| | 6 | 주가를 움직이는 것들 | 펼침 |
| 계산 방법 | 7 | 왜 "얼마가 된다"고 말하지 않나요 | **접힘** |

**성적표는 펼쳐 두고, 그 안의 예측 기록 표(날짜별 8열)만 접는다.**
요약 성적(구간 적중률·평균 범위 폭·비교 기준 대비)은 항상 보이고,
원본 기록은 볼 사람만 펼친다.

접기는 **`<details>`/`<summary>` 표준 요소**를 쓴다. 자바스크립트 없이 동작하고
스크린리더·키보드 조작·인쇄가 공짜로 따라온다. 직접 만든 토글은 쓰지 않는다.

접힌 섹션은 **첫 화면의 `›` 링크로 이동할 때 자동으로 펼쳐진다**
(`details.open = true` 후 스크롤).

### 4.3 종목 탐색

상단 종목 이름(`삼성전자 ▾`)을 누르면 아래에서 시트가 올라온다.

```
┌───────────────────────┐
│ 종목 고르기         ✕ │
├───────────────────────┤
│ 🔍 종목 이름·코드 검색 │
│                       │
│ 반도체                 │
│   삼성전자   268,000 ▲ │
│   SK하이닉스 812,000 ▲ │
└───────────────────────┘
```

- 카테고리는 `symbols.json`에 `category` 필드를 더해 표현한다.
  값이 없으면 "전체" 한 묶음으로 나온다 — **로드맵 4번 전까지는 이 상태다.**
- 시세는 이미 받아둔 데이터가 있는 종목만 표시하고, 없으면 이름만 보여준다.
- `role="dialog"` + `aria-modal`, ESC·배경 클릭·닫기 버튼으로 닫히고,
  열릴 때 검색창에 초점이 간다. 닫으면 초점이 원래 버튼으로 돌아온다.
  차트 확대 모달과 같은 규칙을 쓴다.
- 종목이 5개 이하면 검색창을 숨긴다.

## 5. 파일·주소 구조 — 지금 그대로 둔다

### 5.1 결정

`index.html` 단일 파일, `?code=` 방식 종목 전환을 **그대로 유지한다.**
종목별 정적 주소(`/005930/`)와 자산 분리(`assets/app.css`, `assets/app.js`)는 하지 않는다.

### 5.2 그래서 못 하게 되는 것

**카카오톡·페이스북·구글 크롤러는 자바스크립트를 실행하지 않는다.**
지금은 자바스크립트로 제목을 바꾸므로, 크롤러에게는 HTML에 박힌 제목 하나만 보인다.

| | 가능 | 불가능 |
|---|---|---|
| 링크 공유 | 앱 전체를 하나로 소개 | 종목별로 다른 제목·설명 |
| 검색 노출 | 사이트 하나로 색인 | 종목별 페이지 색인 |

### 5.3 왜 이 선택이 합리적인가

바꿨을 때 생기는 위험 네 가지 중 셋이 **"고장 나도 화면에 티가 안 나는"** 종류였다.

1. 모델 이중 구현 검사(`parity.js`)가 옛 위치를 보게 되어 조용히 무력화
2. 찍혀 나온 파일을 직접 고치면 다음 갱신에 조용히 사라짐
3. 서비스 워커가 사용자를 옛 화면에 가둠
4. 한번 퍼진 주소는 되돌릴 수 없음 — **장치로 막을 수 없는 유일한 것**

지금 방문자가 많지 않아 **얻는 것(공유·검색 유입)의 실제 크기를 모른다.**
크기를 모르는 이득을 위해 되돌릴 수 없는 위험을 지는 것은 순서가 틀렸다.

### 5.4 언제 다시 꺼내나

아래 중 하나가 실제로 관찰되면 다시 검토한다.

- 링크 공유로 들어오는 방문이 의미 있게 생겼는데 **종목이 틀리게 표시돼 문제가 된 사례**가 나올 때
- 검색으로 들어오는 유입을 늘리는 것이 목표가 될 때 (로드맵 5번 랜딩과 함께)
- 종목이 늘어 한 페이지가 감당하기 어려워질 때 (로드맵 4번 진행 중)

로드맵 5번(랜딩)에서 반드시 다시 마주칠 결정이므로, **그때 이 문서를 먼저 읽을 것.**

## 6. 공개 서비스 기본기

### 6.1 접근성

- 접기는 `<details>`, 시트는 `role="dialog"` + 초점 관리
- 랜드마크 — `<header>` / `<nav>` / `<main>` / `<footer>`
- 표에 시각적으로 숨긴 `<caption>`, `<th scope="col">`
- **색만으로 정보를 전달하지 않는다** — ▲▼ 기호 병행(이미 지키고 있다)
- 본문 명도 대비 4.5:1 이상 확인. 특히 `--sub`(#5b6785)와 `.warnline` 안 글자
- `prefers-reduced-motion: reduce`면 차트 애니메이션을 끈다
- 터치 목표 최소 44px 유지(이미 적용)

### 6.2 첫 로드 성능

- `Chart.js`를 **`defer`** 로 — 지금은 `<head>`에서 동기 로드라 첫 화면 표시를 막는다
- 차트는 화면에 들어올 때 그린다(`IntersectionObserver`).
  첫 화면에 차트가 없으므로 그만큼 첫 표시가 빨라진다
- 파일 분리를 하지 않으므로 캐시 효율 개선은 이번 범위 밖이다

### 6.3 면책·법적 표시

- 첫 화면 요약 블록 바로 아래 한 줄 — "참고용이에요. 투자 권유가 아니에요."
- 전문은 지금처럼 맨 아래 유지
- **투자 권유로 읽힐 표현 금지 규칙은 그대로다**(CLAUDE.md 문체 규칙)

### 6.4 공유·검색 메타 — 지금 구조에서 할 수 있는 것

종목별로는 못 하지만, **지금 틀리게 나가는 것을 안 틀리게** 만들 수는 있다.

- 지금 `<title>`·`description`이 "삼성전자"로 고정돼 있다.
  하이닉스 링크를 공유하면 **틀린 정보가 나간다.**
  → **종목 중립 문구로 바꾼다.** 예: "주가 리포트 — 앞으로 얼마나 흔들릴까요"
  (자바스크립트가 뜨면 지금처럼 종목명으로 바뀌는 동작은 그대로 둔다)
- `og:title`·`og:description`·`og:image`·`twitter:card` 추가 —
  지금은 아예 없어서 공유하면 밋밋한 링크만 나간다
- `og:image`는 공통 이미지 하나(1200×630). 기존 아이콘과 같은 방식으로
  Node에서 PNG를 직접 인코딩해 만든다(`scripts/tools/make_og.js`)
- `robots.txt` + `sitemap.xml`(주소 하나) 추가

**이건 틀린 것을 고치는 작업이지 유입을 늘리는 작업이 아니다.** 그 구분을 유지한다.

## 8. 위험과 대응

파일·주소 구조를 그대로 두기로 해서 위험이 크게 줄었다. 남은 것은 셋이다.

| 위험 | 왜 위험한가 | 대응 |
|---|---|---|
| 서비스 워커가 옛 화면에 가둠 | 화면을 고쳤는데 캐시 버전을 안 올리면 사용자가 옛 화면에서 못 나온다 | `sw.js`의 `CACHE` 버전을 올린다. `preflight.js`가 이미 경고한다 |
| 접기가 정보를 숨기는 것으로 읽힘 | 이 앱은 한계까지 다 보여주는 것이 정체성이다 | 접는 것은 방법론과 예측 기록 표 **둘뿐**. 제목은 항상 보이고, 첫 화면 링크로 들어가면 자동으로 펼쳐진다 |
| 첫 화면이 390px를 넘음 | 스크롤 없이 끝난다는 목표가 깨진다 | iframe 폭 검사로 실측한다. 넘으면 면책 한 줄을 첫 화면 밖으로 내린다 |

## 9. 완료 기준

구현이 끝났다고 말하려면 아래가 전부 통과해야 한다.

1. `node scripts/verify/preflight.js` 통과 (모델 일치·JSON·캐시 버전)
2. 320 / 360 / 390 / 414 / 768 / 1200px × 두 종목 — **가로 넘침 0**
3. 콘솔 에러 0 (브라우저 확장 프로그램 것 2건 제외)
4. 서버를 끈 상태에서 새로고침 — 차트·시세·수급·시장 정보가 전부 뜬다
5. 첫 화면이 390px에서 스크롤 없이 들어온다
6. 첫 화면의 `왜요? ›`·`성적 ›` 링크가 접힌 섹션을 펼치며 이동한다
